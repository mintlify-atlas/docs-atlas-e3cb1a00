---
title: "Multi-Node Cluster Deployment for CubeSandbox"
description: "Expand a single-node CubeSandbox deployment into a multi-node cluster by adding compute-only nodes that register to the control plane."
---

A multi-node CubeSandbox cluster distributes sandbox execution across multiple physical machines. The control node runs the full stack — orchestration, API, proxy, and databases — while each compute node runs only the runtime components and registers itself to the control plane.

<Note>
You must have a working control node deployed before adding compute nodes. See [Single-node deployment](/deployment/single-node) to set up the control node first.
</Note>

## Architecture overview

```
┌─────────────────────────────────────────┐
│           Control Node                  │
│  CubeMaster, cube-api, CubeProxy,      │
│  CoreDNS, MySQL, Redis,                │
│  Cubelet, network-agent                 │
└──────────────────┬──────────────────────┘
                   │  /internal/meta API
       ┌───────────┼───────────┐
       ▼           ▼           ▼
┌────────────┐┌────────────┐┌────────────┐
│ Compute #1 ││ Compute #2 ││ Compute #N │
│ Cubelet    ││ Cubelet    ││ Cubelet    │
│ net-agent  ││ net-agent  ││ net-agent  │
└────────────┘└────────────┘└────────────┘
```

- The **control node** runs the full stack: orchestration (CubeMaster), API gateway (cube-api), proxy (CubeProxy + CoreDNS), databases (MySQL + Redis), and also acts as a compute node itself.
- Each **compute node** runs only `Cubelet` and `network-agent`. It registers to the control-plane CubeMaster and receives sandbox scheduling requests.

## Prerequisites

Each compute node must meet the same hardware and software requirements as the control node:

- **Physical machine or bare-metal server** — nested virtualization is not supported
- **x86_64** architecture with **KVM enabled** (`ls /dev/kvm`)
- **Docker** installed and running
- **Network connectivity** to the control node — specifically to CubeMaster on port `8089` (default)

For the full requirements list, see [Single-node deployment — Prerequisites](/deployment/single-node#prerequisites).

## Step 1: Prepare the release bundle

Use the **same release bundle** that was built for the control node. Copy it to the compute node and extract it:

```bash
tar -xzf cube-sandbox-one-click-<version>.tar.gz
cd cube-sandbox-one-click-<version>
```

## Step 2: Configure environment variables

```bash
cp env.example .env
```

Edit `.env` and set the following variables:

```bash
ONE_CLICK_DEPLOY_ROLE=compute
CUBE_SANDBOX_NODE_IP=<current-node-ip>
ONE_CLICK_CONTROL_PLANE_IP=<control-plane-ip>
```

| Variable | Description |
|---|---|
| `ONE_CLICK_DEPLOY_ROLE` | Must be set to `compute` for compute-only nodes |
| `CUBE_SANDBOX_NODE_IP` | This node's primary network interface IP (must be a routable IP, not `127.0.0.1`) |
| `ONE_CLICK_CONTROL_PLANE_IP` | The control node's IP; automatically expanded to `<ip>:8089` for CubeMaster |

If CubeMaster runs on a non-default port, specify the full address explicitly:

```bash
ONE_CLICK_CONTROL_PLANE_CUBEMASTER_ADDR=<control-plane-ip>:8089
```

`ONE_CLICK_CONTROL_PLANE_CUBEMASTER_ADDR` takes precedence over `ONE_CLICK_CONTROL_PLANE_IP` when both are set.

## Step 3: Install

```bash
sudo ./install-compute.sh
```

The compute-node install script will:

1. Install only `Cubelet`, `network-agent`, `cube-shim`, `cube-image`, `cube-kernel-scf`, and the runtime scripts
2. Start only the host processes `network-agent` and `cubelet`
3. Automatically point Cubelet's `meta_server_endpoint` to the control-plane CubeMaster
4. Register the node and report status through the control plane `/internal/meta` API

## Verifying the deployment

### Health check on the compute node

```bash
sudo ./smoke.sh
```

In compute-node mode, `quickcheck.sh` verifies:

- Local `network-agent` health
- Reachability of the control-plane CubeMaster
- That the current node appears under `/internal/meta/nodes/{node_id}` on the control plane

### Verify from the control node

On the control node, confirm the compute node has registered:

```bash
curl http://127.0.0.1:8089/internal/meta/nodes
```

The response includes each registered node's IP and health status.

## Common operations

### Stop compute node services

```bash
sudo ./down.sh
```

In compute-node mode, this only stops `cubelet` and `network-agent`. It does not affect the control plane or other compute nodes.

### Reinstall

To reinstall a compute node, run `install-compute.sh` again. The script automatically stops the existing deployment before installing.

### View logs

| Component | Log path |
|---|---|
| Cubelet | `/data/log/Cubelet/` |
| CubeShim | `/data/log/CubeShim/` |
| Hypervisor (VMM) | `/data/log/CubeVmm/` |
| Runtime PID files | `/var/run/cube-sandbox-one-click/` |
| Process stdout/stderr | `/var/log/cube-sandbox-one-click/` |

For control-node log paths, see [Single-node deployment — View logs](/deployment/single-node#view-logs).

## Configuration reference

Compute nodes use the same `.env` file format. The following variables are specific to or particularly relevant for compute-node deployments:

| Variable | Default | Description |
|---|---|---|
| `ONE_CLICK_DEPLOY_ROLE` | `control` | Must be set to `compute` |
| `CUBE_SANDBOX_NODE_IP` | auto-detected | **Required.** This node's primary network interface IP |
| `ONE_CLICK_CONTROL_PLANE_IP` | empty | Control-plane host IP; expanded to `<ip>:8089` by default |
| `ONE_CLICK_CONTROL_PLANE_CUBEMASTER_ADDR` | empty | Explicit CubeMaster address; takes precedence over `ONE_CLICK_CONTROL_PLANE_IP` |
| `ONE_CLICK_INSTALL_PREFIX` | `/usr/local/services/cubetoolbox` | Installation directory |
| `ONE_CLICK_RUN_QUICKCHECK` | `1` | Run health check after installation |

For the full configuration reference (build-time options, database, proxy settings), see [Single-node deployment — Configuration reference](/deployment/single-node#configuration-reference).

## Troubleshooting

<AccordionGroup>
  <Accordion title="Compute node cannot reach CubeMaster">
    Verify network connectivity from the compute node:

    ```bash
    curl http://<control-plane-ip>:8089/internal/meta/nodes
    ```

    If this fails, check:
    - Firewall rules on the control node — port `8089` must be accessible from compute nodes
    - The value of `ONE_CLICK_CONTROL_PLANE_IP` or `ONE_CLICK_CONTROL_PLANE_CUBEMASTER_ADDR` in `.env`
  </Accordion>

  <Accordion title="Node not appearing in control plane">
    If `smoke.sh` passes locally but the node does not appear in the control plane:

    1. Check Cubelet logs: `/data/log/Cubelet/`
    2. Verify that `meta_server_endpoint` in the Cubelet config points to the correct CubeMaster address
    3. Ensure `CUBE_SANDBOX_NODE_IP` is set to a routable IP — not `127.0.0.1`
  </Accordion>

  <Accordion title="KVM not available on compute node">
    Each compute node requires KVM. Verify with:

    ```bash
    ls /dev/kvm
    lsmod | grep kvm
    ```

    For Intel CPUs you need the `kvm_intel` module; for AMD, `kvm_amd`. Nested virtualization is not supported.
  </Accordion>
</AccordionGroup>
