---
title: "Quickstart: Run Your First CubeSandbox in Minutes"
description: "Step-by-step guide to install CubeSandbox, create a code-interpreter template, and execute agent code in a hardware-isolated KVM MicroVM sandbox."
---

CubeSandbox requires a KVM-enabled x86_64 Linux environment to run its hardware-isolated MicroVMs. This guide walks you through booting a disposable development VM (for those without a bare-metal server), installing CubeSandbox with the one-click installer, creating a sandbox template, and running your first agent code using the E2B SDK — all in four steps.

<Note>
  If you already have a KVM-enabled x86_64 Linux bare-metal server, you can skip Step 1 and run the Step 2 installer directly on that server.
</Note>

## Prerequisites

Any one of the following hosts works:

- **WSL 2 on Windows** — Windows 11 22H2+ with nested virtualization enabled in WSL
- **An x86_64 Linux physical machine**
- **A Linux VM with nested virtualization enabled** — for example, Ubuntu 22.04 on VMware with "Virtualize Intel VT-x/EPT or AMD-V/RVI" enabled in the VM's CPU settings
- **An x86_64 bare-metal Linux server**

All environments must satisfy these common requirements:

1. `/dev/kvm` exists and is read/writable
2. **Docker** and **QEMU** are installed and running
3. Internet access to clone the repository, download the release bundle, and pull Docker images

## Installation steps

<Steps>
  <Step title="Boot the development VM">
    If you do not have a bare-metal server, clone the repository and use the `dev-env/` scripts to boot a disposable OpenCloudOS 9 VM on your host.

    Before running the commands below, ensure `qemu`, `qemu-img`, and `ripgrep` are installed on your Linux machine.

    In your **first terminal**, run:

    <Tabs>
      <Tab title="Global">
        ```bash
        git clone https://github.com/tencentcloud/CubeSandbox.git
        cd CubeSandbox/dev-env
        ./prepare_image.sh   # one-off: download + init the OpenCloudOS 9 image
        ./run_vm.sh          # boot the VM; keep this terminal open (Ctrl+a x to power off)
        ```
      </Tab>
      <Tab title="Mainland China mirror">
        ```bash
        git clone https://cnb.cool/CubeSandbox/CubeSandbox
        cd CubeSandbox/dev-env
        ./prepare_image.sh   # one-off: download + init the OpenCloudOS 9 image
        ./run_vm.sh          # boot the VM; keep this terminal open (Ctrl+a x to power off)
        ```
      </Tab>
    </Tabs>

    In a **second terminal**, log into the VM:

    ```bash
    cd CubeSandbox/dev-env
    ./login.sh   # SSH into the VM as root
    ```

    All the following steps run inside this VM shell. See [Dev Environment](/dev-environment) for host self-check steps, port mappings, environment overrides, and troubleshooting.
  </Step>

  <Step title="Install CubeSandbox">
    Inside the dev VM (or directly on your bare-metal server), run the one-click installer:

    <Tabs>
      <Tab title="Global">
        ```bash
        curl -sL https://github.com/tencentcloud/CubeSandbox/raw/master/deploy/one-click/online-install.sh | bash
        ```
      </Tab>
      <Tab title="Mainland China mirror">
        ```bash
        curl -sL https://cnb.cool/CubeSandbox/CubeSandbox/-/git/raw/master/deploy/one-click/online-install.sh | MIRROR=cn bash
        ```
      </Tab>
    </Tabs>

    The installer sets up:

    - E2B-compatible REST API listening on port `3000`
    - CubeMaster, Cubelet, network-agent, and CubeShim running as host processes
    - MySQL and Redis managed via Docker Compose
    - CubeProxy with TLS (mkcert) and CoreDNS for `cube.app` domain routing

    After installation completes, `cubemastercli` and `cubecli` are symlinked into `/usr/local/bin`.
  </Step>

  <Step title="Create a template">
    Create a code-interpreter template from the prebuilt image:

    ```bash
    cubemastercli tpl create-from-image \
      --image ccr.ccs.tencentyun.com/ags-image/sandbox-code:latest \
      --writable-layer-size 1G \
      --expose-port 49999 \
      --expose-port 49983 \
      --probe 49999
    ```

    The command outputs a `job_id`. Monitor the build with:

    ```bash
    cubemastercli tpl watch --job-id <job_id>
    ```

    <Warning>
      The image is fairly large. Downloading, extracting, and building the template can take several minutes — wait for the status to reach `READY` before continuing.
    </Warning>

    Note the **template ID** (`template_id`) from the output — you will need it in the next step. For the full template creation workflow and additional CLI options, see [Creating templates from OCI images](/templates/from-oci-image).
  </Step>

  <Step title="Run your first agent">
    Install the Python SDK inside the VM:

    ```bash
    yum install -y python3 python3-pip
    pip install e2b-code-interpreter
    ```

    Set the required environment variables, replacing `<your-template-id>` with the template ID from Step 3:

    ```bash
    export E2B_API_URL="http://127.0.0.1:3000"
    export E2B_API_KEY="dummy"
    export CUBE_TEMPLATE_ID="<your-template-id>"
    export SSL_CERT_FILE="/root/.local/share/mkcert/rootCA.pem"
    ```

    | Variable | Description |
    |---|---|
    | `E2B_API_URL` | Points the E2B SDK to your local CubeSandbox instance instead of E2B cloud |
    | `E2B_API_KEY` | The SDK requires a non-empty value; any string works |
    | `CUBE_TEMPLATE_ID` | The template ID obtained in Step 3 |
    | `SSL_CERT_FILE` | mkcert CA root certificate for HTTPS connections to the sandbox |

    Run code inside a hardware-isolated sandbox:

    ```python
    import os
    from e2b_code_interpreter import Sandbox  # drop-in E2B SDK

    # CubeSandbox transparently intercepts all requests
    with Sandbox.create(template=os.environ["CUBE_TEMPLATE_ID"]) as sandbox:
        result = sandbox.run_code("print('Hello from Cube Sandbox, safely isolated!')")
        print(result)
    ```
  </Step>
</Steps>
